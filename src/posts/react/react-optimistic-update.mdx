**Optimistic Update**(낙관적 업데이트)는 사용자 경험을 향상시키는 중요한 기법으로, UI가 서버의 응답을 기다리지 않고 **즉시 변경된 상태를 반영**할 수 있는 방법입니다. TanStack Query는 이를 다양한 상황에서 간단히 구현할 수 있는 함수를 제공하기 때문에 이번 글에서는 일반 데이터와 무한 스크롤 데이터 각각에서 Optimistic Update를 구현하는 방법을 살펴보겠습니다.

## Optimistic Update
Optimistic Update는 사용자가 수행한 작업(예: 추가, 삭제, 수정)이 성공적으로 처리될 것이라고 가정하고, 서버의 응답 전 UI를 즉시 갱신하는 기술입니다. 이를 통해 사용자 경험(UX)을 크게 향상시킬 수 있습니다.

Optimistic Update는 서버 요청이 성공할 것을 **"낙관적으로"** 가정하기 때문에 이름이 붙여졌으며, 특히 서버 응답 시간이 길거나 네트워크 상태가 불안정한 상황에서도 부드럽고 직관적인 인터페이스를 제공합니다.

### Optimistic Update의 주요 흐름

Optimistic Update는 아래와 같은 흐름으로 처리되며 Tanstack Query에서는 아래의 흐름을 따르는 함수를 제공합니다.

1. 사용자가 작업을 요청합니다.
2. UI가 변경된 상태를 즉시 반영합니다.
3. 서버에 작업 요청을 보냅니다.
4. 서버가 작업을 성공적으로 처리하면 UI를 유지합니다.
5. 서버가 실패를 반환하면 UI를 롤백합니다.


## Tanstck Query에서 사용하기

TanStack Query는 `onMutate`, `onError`, `setQueryData`, `getQueryData` 등과 같은 옵션을 사용해 낙관적 업데이트를 쉽게 구현할 수 있습니다.

### 일반 데이터에서 사용

일반 데이터에서 사용할 경우 아래의 코드처럼 `onMutate`(서버 요청 전) 함수로 클라이언트에서 `cancelQueries`함수를 사용해 쿼리를 취소하고, `setQueryData`함수를 사용해 Post의 like를 변경하고, `getQueryData`사용해 롤백을 위한 이전 상태를 반환합니다. 

이 때 반환한 값은 `onError`(에러가 발생했을 때) **context**로 사용이 가능하며, 이 값으로 값을 이전상태와 같게 해 줍니다.

```tsx
interface Post {
  id: number;
  title: string;
  isLike: boolean;
}

const LikeButton = ({ postId, isLike }:{
    postId:string;
    isLike:boolean;
}) => {

const { mutate } = useMutation({
  mutationFn: likePost,
  onMutate: async () => {
    await queryClient.cancelQueries({ queryKey: ['post', postId] })

    // 이전 데이터 기억하기
    const previousPost = queryClient.getQueryData<Post>(['post', postId])

    // 클라이언트에서 상태 변경
    queryClient.setQueryData(['post', postId], (oldData) => {
        if (!oldData) return oldData;
        return { ...oldData, isLike: !isLike };
    })

    // onMutate에서 return한 값은 onError의 context로 사용가능
    return { previousPost, postId }
  },

  // 에러가 발생했을 경우 이전의 데이터로 돌림
  onError: (err, data, context) => {
    queryClient.setQueryData(
      ['post', context.previousPost.id],
      context.previousTodo,
    )
  },
})

  return (
    <button onClick={() => mutate()}>
      Like
    </button>
  );
};
```


### 무한 스크롤 데이터에서 사용

무한스크롤을 할 때 사용할 경우 일반 데이터에서 사용하는 경우와 다르게 `setQueryData`의 제네릭 타입을 `InfinitePageData`로 감싸서 전달하며, 해당 배열 내에서 같은 id를 찾아 값을 변경해 줍니다. 이 때 `InfinitePageData`는 백엔드에서 어떤 값을 전달하냐에 따라 달라지게 됩니다.

```tsx
interface Post {
  id: number;
  title: string;
  isLike: boolean;
}

type InfinitePageData = {
  pages: { list: Post[] }[];
};

const LikeButton = ({ postId, isLike }:{
    postId:string;
    isLike:boolean;
}) => {

const { mutate } = useMutation({
  mutationFn: likePost,
  onMutate: async () => {
    await queryClient.cancelQueries({ queryKey: ['postList', postId] })

    // 이전 데이터 기억하기
    const previousPost = queryClient.getQueryData<Post>(['postList', postId])

    // 클라이언트에서 상태 변경
    queryClient.setQueryData<InfinitePageData>(
    ['postList', postId],
    (oldData) => {
        if (!oldData) return oldData;
        return {
        ...oldData,
          pages: oldData.pages?.map((page) => ({
            ...page,
            list: page.list.map((item) =>{
              if(item.id !== postId) return item;
              return {...item, isLike: !isLike}
            }),
          })),
        };
    }
    );

    // onMutate에서 return한 값은 onError의 context로 사용가능
    return { previousPost, postId }
  },

  // 에러가 발생했을 경우 이전의 데이터로 돌림
  onError: (err, data, context) => {
    queryClient.setQueryData(
      ['post', context.previousPost.id],
      context.previousTodo,
    )
  },
})

  return (
    <button onClick={() => mutate()}>
      Like
    </button>
  );
};

```
## 마치며

일반 데이터와 무한 스크롤 데이터에서 낙관적 업데이트를 구현하면서, 두 방식이 비슷하면서도 각기 다른 접근이 필요하다는 것을 알게 되었습니다. 특히, TanStack Query V5에서 제공하는 onMutate, onError, setQueryData 함수는 이전 버전보다 더욱 직관적이고 간편하게 설계되어, 개발자 입장에서 훨씬 효율적으로 사용할 수 있었습니다. 이러한 개선 덕분에 복잡한 작업도 쉽게 처리할 수 있었고, 개발 경험이 한층 편리해졌다는 점이 인상적이었습니다.
