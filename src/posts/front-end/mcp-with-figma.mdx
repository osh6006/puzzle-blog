AI가 점점 더 똑똑해지고 있지만, 여전히 답답한 순간들이 있습니다. 예를 들어 "이 디자인 어때?"라고 묻고 싶은데, AI는 정작 Figma 파일을 열 줄도 모릅니다. GitHub에 있는 코드 변경 사항을 요약해달라 해도, 해당 저장소에 접근할 수 없다면 아무 소용이 없죠.

우리는 이제 단순한 대화형 AI를 넘어서, **실제 도구와 데이터를 함께 다룰 수 있는 AI**를 원합니다.  
그 바탕에 있는 기술이 바로 **Model Context Protocol**(MCP)입니다.

이번 글에서는 MCP가 무엇인지 간단하게 설명하고,  
**Cursor와 Figma를 연결해 직접 MCP를 체험해보는 방법**까지 정리해보았습니다.

## AI가 도구를 쓸 수 있다면?

![](https://res.cloudinary.com/dxesudkxn/image/upload/v1743763566/blog/oobvfbw1kpvdxfc5chya.png)

생각해봅시다. AI가 여러분의 로컬 파일을 열어보고, Figma에서 디자인을 읽고, GitHub에서 PR을 열고, 심지어 사내 데이터베이스에 있는 값을 꺼내 쓸 수 있다면?

우리는 AI에게 그저 질문을 던지는 게 아니라, **"도와달라"고 요청할 수 있게 됩니다.**

이건 단순한 모델 성능의 문제가 아니라, **AI가 도구와 연결될 수 있는지의 문제**입니다. 그리고 이걸 가능하게 해주는 게 바로 MCP입니다.

---

## Model Context Protocol(MCP)이란?

MCP는 AI가 외부 도구들과 통신할 수 있게 도와주는 **표준 프로토콜**입니다.  
쉽게 말해, **AI 전용의 USB-C** 같은 존재입니다. 기존에는 API마다 제각각 방식으로 연동해야 했지만 여러 도구를 활용하려면 (Slack을 붙이면 Slack API, Figma는 Figma API...) AI 개발자 입장에서 번거롭고 확장도 어려웠습니다.

하지만 MCP는 이런 복잡한 연결을 단순화합니다.

- **AI가 외부 도구에 안전하게 접근할 수 있도록 연결해주고**  
- **도구 쪽에서는 필요한 정보나 기능만 골라 노출할 수 있게 해줍니다**

그 결과, AI는 더 이상 "그건 몰라요"가 아니라 "**Figma에서 확인해봤는데요…**"로 훨씬 자세하게 대답해 줄 수 있게 되었습니다.

## 어떻게 작동할까?

![](https://res.cloudinary.com/dxesudkxn/image/upload/v1743765569/blog/svmkja0refhv2itdo9di.webp)

MCP는 간단하게 **Host, Client, Server**로 구성되어 있는데, 각 요소는 역할이 명확히 구분되며, 서로 표준화된 방식으로 연결되어 AI가 외부 도구와 자연스럽게 협업할 수 있도록 돕습니다.

### 🧠 Host
AI가 실행되는 애플리케이션입니다. Claude, Cursor, 혹은 여러분이 만든 웹 서비스나 챗봇 앱도 MCP Host가 될 수 있습니다. 사용자는 여기에서 AI에게 질문을 던지고, 결과를 받습니다. Host는 내부에 MCP 클라이언트를 포함하고 있으며, AI가 외부 MCP 서버와 통신할 수 있도록 기반을 제공합니다.

### 🔌 Client
Host 내부에 포함된 MCP 클라이언트는 특정 MCP 서버와 통신하는 중간 연결자 역할을 합니다. 예를 들어 사용자가 “디자인을 요약해줘”라고 질문하면, 클라이언트는 Figma MCP 서버에 요청을 보내고 데이터를 받아옵니다. 하나의 Host는 여러 MCP 클라이언트를 동시에 운영할 수 있어, 다양한 서버(GitHub, Slack, Notion 등)와 병렬 연결이 가능합니다.

### 📡 Server
외부 도구 쪽에서 실행되는 구성 요소로, Figma, GitHub, Google Drive, 내부 데이터베이스 등 실제 정보를 가지고 있는 시스템을 MCP 인터페이스로 노출합니다.

- 리소스(Resources): 읽기 전용 데이터. 예를 들어 “디자인 파일 내용”, “이슈 목록”, “문서 내 텍스트”.

- 툴(Tools): AI가 실행할 수 있는 동작. 예: “PR 생성하기”, “Slack에 메시지 보내기”, “파일 요약하기”.

- 프롬프트(Prompts): AI가 해당 리소스를 어떻게 활용하면 좋을지 안내하는 가이드 문장.

각 서버는 JSON-RPC 기반의 표준 메시지를 통해 클라이언트와 통신하며, 기능 목록을 제공하고 요청을 처리한 뒤 결과를 반환합니다.

## Cursor + Figma 로 직접 체험해보기

실제로 MCP를 통해 AI가 도구를 활용하는 걸 보고 싶다면, Cursor IDE와 Figma를 연결해보는 게 가장 간단하고 흥미로운 방법입니다.

프론트엔드 개발자인 저는 평소 Figma를 자주 사용하는데, Claude가 디자인을 읽고 피드백을 제안하는 과정을 직접 보며, 생각보다 훨씬 편리하게 느껴졌고 MCP를 적절히 활용한다면 실무에서 큰 도움이 될 수 있겠다는 생각이 들었습니다


### 1. Figma MCP 서버 설치
 
1. [Figma-Context-MCP](https://github.com/GLips/Figma-Context-MCP) Repository를 clone 합니다.
2. Figma에 들어가서 프로필 클릭 후 Settings에 들어간 다음 Security탭의 하위에 있는 Personal Access Token 영역에서 Generate new token을 눌러 새로운 토큰을 발급 받습니다.
3. clone받은 Repository의 .env 파일에 생성한 `FIGMA_API_KEY`를 넣어 줍니다.
4. 의존성 설치 후 아래의 명령어를 입력하여 로컬 서버를 실행해 줍니다.
```powershell
npx figma-developer-mcp --figma-api-key=여기에 피그마 토큰을 넣어주세요
```
### 2. Cursor에서 Figma MCP 연결하기

1. Cursor Settings를 열고 좌측 탭 중 MCP를 클릭합니다.
2. 우측 상단 Add new MCP server를 클릭 후 이름을 설정하고, 
- command말고 Server send Event Type으로 설정합니다.
- Server URL에 FIgma MCP 프로젝트 로컬 포트 번호에 맞춰 위와 같이 적어줍니다.
3. 이제 커서 Chat을 켜고 Agent모드에서 Figma link를 붙여넣고 구현을 요청합니다.
- 피그마 요소 우클릭 > Copy link to selection
4. 또는 Figma MCP 서버와 Cursor가 정상적으로 연결되었다면 해당 link를 붙여넣고 관련 프롬프트(e.g. 피그마 디자인을 읽고 구현해줘)를 넣으면 아래와 같이 Called MCP tool과 파라미터들이 보이고 프롬프트에 따라 코드들을 생성하기 시작합니다.

## 또 어디에 쓸 수 있을까?

### ✨ 개발 자동화

- PR 생성, 코드 리뷰, 이슈 요약 등 반복적인 작업을 AI가 대신 처리할 수 있어, 개발자는 핵심 로직과 문제 해결에 집중할 수 있습니다.

- CI/CD 파이프라인과 연동해 배포 알림, 테스트 결과 요약 등을 자동화하는 것도 가능합니다.

### 🧩 사내 데이터 연동

- Slack의 회의 로그를 요약해 회의록을 자동 생성하거나, Google Drive의 문서를 불러와 주요 내용을 정리할 수 있습니다.

- Postgres 등 데이터베이스에 연결해 실시간 데이터 조회, 리포트 생성 등도 AI를 통해 간편하게 수행할 수 있습니다.

### 🧠 개인 생산성

- 작성 중인 노트를 요약하거나, 산만한 일정표를 정리해주는 등의 개인 업무에도 활용할 수 있습니다.

- 폴더 구조 분석 및 파일 분류, 작업 리마인드 생성 등 사소하지만 시간을 잡아먹는 일을 효율적으로 처리할 수 있습니다.

- 노트 요약

- 일정 정리

- 파일 분류 및 추천

## 마치며

AI는 처음부터 개발자 업무에 큰 변화를 최근에는 단순한 질문 응답을 넘어, 특정 맥락을 이해하고 적절한 도구를 통해 작업을 이어가는 방향으로 진화하고 있습니다. MCP는 이러한 흐름 속에서 중요한 역할을 담당합니다. 오늘 글에서 소개한 Cursor와 Figma뿐 아니라, 다양한 AI 툴에서도 MCP가 더 창의적으로 활용된다면 개인뿐 아니라 팀 단위에서도 훨씬 유연하고 강력한 협업이 가능해질 것으로 기대됩니다.
